# Skills 系统与工具重复 Bug 修复

## 修改了什么

### 修复1：LLM 调用 duplicate tool names 报错

**涉及文件**：`tui_main.py:727-731`、`main.py:775`、`main.py:1101`

**问题**：`all_tools = tools + subagent_tools` 或 `tools = tools + subagent_tools` 导致工具名重复。
- `tools` = `get_tools_by_names(GENERAL.allowed_tools)` 已含 `search_code`
- `_build_subagent_tools(ctx)` 返回 `ctx.tools`（同一份列表）
- 两者直接拼接导致 `search_code` 出现两次，LLM API 返回 400 错误

**修复**：改为按 `tool.name` 去重合并，只添加尚未出现的工具。三处全部修复：
- `tui_main.py` `_do_chat` 函数
- `main.py` `_handle_chat` 方法（主 Agent）
- `main.py` `_spawn_subagent` 方法（子 Agent spawn）

### 修复2：skill-creator 初始技能未加载

**涉及文件**：`tui_main.py:1148-1183`、`main.py:461-499`

**问题**：`_init_skills` 仅扫描 `get_skills_dir()` 返回的单一目录，该路径依赖 `__main__.__file__`，不同启动方式下可能找不到 `skills/` 目录。且加载到任何 skill 后直接返回，不再保证 skill-creator 存在。

**修复**：
1. 扫描多个候选目录（`get_skills_dir()` + 入口文件同级 `skills/`）
2. 加载后显式检查 `skill-creator` 是否已注册，缺失则从项目 `skills/skill-creator/` 补充加载
3. 仅在 registry 仍为空时才回退注册 5 个硬编码技能

## 为何这样修改

- 修复1：`_build_subagent_tools` 设计上是为主 agent 提供子 agent 工具集（含 spawn/eval 等），但实现上直接返回了 `ctx.tools`，与已有工具完全重叠。去重合并是最小改动，不改变语义。
- 修复2：`skill-creator` 是项目内置的技能创建工具，应始终可用。增强路径发现 + 显式兜底确保无论启动方式如何都能注册。用户实际运行的是 `main.py`（CLI 模式），此前只修了 `tui_main.py` 遗漏了 `main.py`。

## 变更的意义

- 消除 LLM API 400 报错，主 Agent 和子 Agent 恢复正常工作
- 用户启动后 `/skills` 命令应能看到 `skill-creator` 而非 5 个硬编码占位技能
- 5 个硬编码技能仅作为无任何 skill 可用时的最后兜底
- `main.py` 和 `tui_main.py` 保持一致的修复策略
