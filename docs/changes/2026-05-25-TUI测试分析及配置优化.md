# Goat TUI 测试分析及配置优化

## 一、问题诊断

### 从 Terminal 输出发现的问题

1. **Playwright 未安装**（高优先级）
   - 错误: `Error: Playwright not installed. Please run: pip install playwright && playwright install chromium`
   - 影响: `web_run`、`web_screenshot` 两个浏览器工具完全不可用
   - 原因: playwright 虽然写在 requirements.txt 中，但未实际安装，也没有安装 Chromium 浏览器

2. **沙箱网络访问受限**（中优先级）
   - `execute_command` 被沙箱拒绝网络访问
   - Windows 下 `WindowsJobSandbox` 使用了 Job Object 的进程数限制（3个），但没有显式阻止网络
   - 实际原因是命令执行在 `async_execute_command` 中通过 `create_sandbox()` 执行，默认有限制

3. **API Key 明文暴露**（安全 - 严重）
   - `setting.json` 直接存储 API Key 明文
   - review_api_key 与主 API Key 相同，增加泄露面
   - 文件已在 `.gitignore` 中，但本地仍有风险

4. **子 Agent 模型未配置**（低优先级）
   - TUI 支持 `ModelRouter` 和 `role_models`，但 setting.json 中未配置
   - 子 Agent 默认使用 `DEFAULT_SUB_MODEL`，可能与主模型不一致

## 二、优化措施

### 1. setting.json 配置完善
- 新增 `sub_model` 字段：子 Agent 默认模型
- 新增 `role_models` 字段：为不同角色指定专用模型
  - review 角色使用更强的 `qwen3.5-plus-2026-04-20` 进行代码审查
  - 其他角色使用 `qwen3.6-35b-a3b`

### 2. 环境变量支持（`tui_main.py`）
- 添加 `.env` 文件加载（python-dotenv）
- 环境变量优先于 setting.json：
  - `API_KEY` → 覆盖 api_key
  - `BASE_URL` → 覆盖 base_url
  - `MODEL` → 覆盖 model
- `.env.example` 提供配置模板
- `.gitignore` 新增 `.env` 相关忽略规则

### 3. 新终端启动支持
- `start_tui.bat`：在当前终端运行 TUI
- `start_tui_new_terminal.bat`：在新窗口中启动 TUI（使用 Windows `start` 命令）
- 双击批处理文件即可运行，无需手动输入命令

### 4. 依赖更新
- `requirements.txt` 新增 `python-dotenv>=1.0.0`
