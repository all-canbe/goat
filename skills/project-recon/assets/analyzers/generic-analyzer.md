# 通用分析器

<!-- @类型: 分析器插件 -->
<!-- @目的: 对未知技术栈的项目进行通用分析 -->

## 适用识别条件

当没有其他分析器匹配时，由编排器自动回退加载此分析器。

## 分析维度

### 维度 1：语言与运行时

**执行动作：**
- 扫描项目根目录，识别配置文件类型
- 推断主要编程语言
- 识别包管理器（npm/pip/maven/gradle/cargo/gem 等）
- 识别运行时版本（Node/Python/Java/Go/Rust 等）

### 维度 2：目录结构

**执行动作：**
- 遍历顶层目录
- 按目录名推断职责（`src/` = 源码，`lib/` = 库，`test/` = 测试 等）
- 深入 `src/` 分析第二层结构
- 跳过 `node_modules/`、`vendor/`、`.git/`、`dist/`、`build/` 等

### 维度 3：依赖分析

**执行动作：**
- 找到依赖声明文件（package.json / requirements.txt / go.mod / Cargo.toml 等）
- 列出核心依赖（Top 10）
- 区分运行时依赖和开发依赖

### 维度 4：模块提取

**执行动作：**
- 按目录结构推断模块边界
- 按文件命名模式推断功能分组
- 按 import/require 语句分析模块间依赖

### 维度 5：入口与配置

**执行动作：**
- 识别应用入口文件（main.* / app.* / index.* / server.*）
- 识别配置文件（.env / config.* / settings.*）
- 识别构建/启动脚本（Makefile / package.json scripts / Dockerfile）

### 维度 6：开发约定

**执行动作：**
- 读取 `.trae/rules/` 目录下所有规则文件
- 检查 lint / format 配置
- 检查 CI/CD 配置

## 模块提取策略

1. 按 `src/` 下的顶层目录推断模块
2. 按文件命名模式分组（如 `*_controller.*`、`*_service.*`）
3. 按 import 关系分析模块间依赖

## 输出格式

返回给编排器的结构化数据：

```
## 分析器输出

### 项目基本信息
{语言/运行时/包管理器/构建工具}

### 目录结构
{目录 → 职责映射表}

### 模块地图
| 模块名 | 职责 | 关键文件 | 依赖关系 |
|--------|------|---------|---------|

### 核心依赖
| 依赖 | 版本 | 用途 |
|------|------|------|

### 开发约定
{规则文件摘要}

### 入口索引
{入口文件路径和说明}
```
