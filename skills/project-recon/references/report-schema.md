# 报告格式规范

<!-- @类型: 格式规范 -->
<!-- @目的: 定义报告的结构标准和校验规则 -->

> 本文档不负责工作流路由。

## 报告文件规范

- 文件名：`project-recon-report.md`
- 位置：项目根目录
- 格式：Markdown

## 必须包含的章节

### 章节 1：项目概要

```markdown
# 项目侦察报告：{项目名称}

> 生成时间：{YYYY-MM-DD HH:mm}
> 侦察工具：project-recon v{版本号}
> 使用分析器：{分析器列表}

| 属性 | 值 |
|------|-----|
| 项目名称 | {名称} |
| 版本 | {版本} |
| 描述 | {一句话描述} |
| 技术栈 | {语言 + 框架} |
| 项目类型 | {Web/小程序/API/全栈/桌面/移动} |
| 构建工具 | {Vite/Webpack/Maven/Gradle/...} |
```

## 质量校验清单

编排器在 `@步骤6: 校验输出` 中必须逐项检查：

- [ ] 所有 7 个章节均已填充，无空章节
- [ ] 模块地图至少有 3 个模块
- [ ] 技术栈详情区分了核心依赖和开发依赖
- [ ] 数据流描述了完整的数据流转路径
- [ ] 开发约定已提取所有 `.trae/rules/` 规则
- [ ] 入口索引至少包含应用入口和路由配置
- [ ] 报告头部注明生成时间和分析器列表
